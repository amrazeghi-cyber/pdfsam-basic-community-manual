# Contributing and Feedback

Thank you for helping improve the PDFsam Basic Community Manual.

## What is useful

Feedback is especially welcome when it includes one or more of the following:

- A correction to an instruction.
- A PDFsam Basic version where behavior differs from the manual.
- A reproducible troubleshooting case and its solution.
- A clearer or shorter workflow for a task already covered.
- A useful real-world example.
- A suggestion for a missing topic.

## How to report feedback

Open a GitHub Issue and describe:

1. The PDFsam Basic version and operating system, when relevant.
2. The manual section involved.
3. What you expected to happen.
4. What actually happened.
5. The correction or improvement you suggest, if known.

Please do not upload confidential, personal, or sensitive PDF documents as examples. Use a non-sensitive sample or describe the structure of the document instead.

## Community notes

Useful feedback may be incorporated into a later release. Contributors can be credited in the changelog or release notes when appropriate and when they want attribution.

The project follows a simple cycle: **publish, test, listen, correct, expand.**
